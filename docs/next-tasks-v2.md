# 次の作業プロンプト集 v2（Sonnet依頼用）— 自己成長エンジン化

`docs/next-tasks.md`（v1: 公開・モバイル・PWA・SW・データ移動）は完了。
v2のゴールは **MEMOを「過去を解釈するアプリ」から「中長期の自己を育てるアプリ」にする**こと。

## 現状診断（このv2が解こうとしている問題）

1. **未来を表すデータ型が一つもない。** `post.type` は `post/repost/quote` のみで、目標・意図・宿題を置く場所がない
2. **レポートが互いを読まない。** `generateReport()` は期間内のpostsしかワークフローに渡さず、過去のレポートは入力にならない
   → AIが毎週出す `suggestion.action` は誰にも追跡されない**開ループ**

①がこの2つを直接叩く。以降はその上に乗る。

各プロンプトは独立したセッションにそのままコピペで投げられる。共通前提は各プロンプト内に埋め込み済み。
推奨順は①→②→③→④→⑤（⑥は小さいのでいつでも／⑦は要判断）。

## ① レポートに記憶を持たせる — 前回の一手の追跡と宿題の持ち越し

```
リポジトリ dr-sakamoto/memo を改修したい。

【アプリの前提】
自分ひとり用のCNS（日記/思考ログ）。依存ゼロの静的Webアプリ。
index.html + css/style.css + js/*.js（ES Modules、ビルドなし）、データは全部localStorage。
週次/月次で、雑記をAIが固定スキーマのJSONに構造化した「レポート」を貯めていく設計。
設計思想は「入力は構造化しない。構造はAIの解釈の側に置く」。ユーザーに入力項目を
増やさせる改修は思想違反になるので絶対にしないこと。

【解きたい問題】
レポートが互いを読まない。js/report.js の generateReport() は期間内のpostsしか
js/workflow.js に渡さず、過去のレポートを一切参照しない。その結果、AIが毎週出す
suggestion.action（次の一手）は誰にも追跡されず、出しっぱなしの開ループになっている。
これを閉じて「先週言われたことをやったか」「先送りしている宿題は何か」が
自動で浮上する状態にしたい。

【やること】
1. js/report.js の REPORT_SCHEMA を拡張し、REPORT_SCHEMA_VERSION を 1 → 2 に上げる。
   追加フィールド:
   - previous_action_review: { status: "done"|"partial"|"not_done"|"unknown", evidence: string }
     前回レポートの suggestion.action を、今期の記録から見て実行できていたかの判定
   - open_loops: [{ label: string, note: string }]（最大5件）
     未解決のまま持ち越されている宿題・保留中の決定
   前回レポートが無い場合は status を "unknown"、open_loops は空配列でよい旨を
   description に明記する。

2. 「持ち越し文脈」の注入を実装する。
   - js/report.js に buildCarryOver(period) を追加。同じ periodType の直近レポート
     1件から suggestion と open_loops を取り出し、短いテキストブロックにする
   - js/workflow.js の runReportWorkflow() に carryOver オプションを追加し、
     buildSinglePassPrompt() と buildSynthesisPrompt() の両方の冒頭に差し込む
   - 文面は「前回、他者としてのあなたはこう提案した。今期の記録の中に、
     それが実行された/されなかった証跡があるか率直に判定せよ」の趣旨にする

3. 後方互換を厳守する。
   - js/workflow.js の reconcile() はドメイン非依存を保つ設計なので、
     新フィールドの正規化はそこに書かず、js/report.js 側の後処理関数に置く
   - 既存のschemaVersion 1のレポートはlocalStorageにそのまま残る。
     js/app.js の reportCardHtml() は r.schemaVersion を見て分岐し、
     v1のレポートでは新セクションを描画しないこと（既存データを壊さない）

4. 表示を追加する（js/app.js）。
   - レポートカードに「前回の一手」バッジ（done=✅ / partial=🔸 / not_done=⭕️）と
     その evidence を1行で。details の中ではなく、手紙と同じ見える階層に置く
   - 「持ち越している宿題」を open_loops のリストとして表示
   - メタ分析カード（#metaCard）に「提案の実行率」を追加。
     schemaVersion 2以降のレポートだけを分母にする

【制約】
- npm依存・ビルドツール・フレームワークを絶対に導入しない
- 既存のlocalStorageデータ（cns.posts.v1 / cns.reports.v1）を破壊しない
- ユーザーの入力項目は増やさない（構造化はAI側の仕事）
- APIプロバイダ（Claude / Gemini）両方で動くこと。Geminiはスキーマをプロンプトで
  誘導する方式なので、スキーマ拡張がプロンプトにも反映されているか確認する

【完了条件】
- 既存のv1レポートが残っている状態でアプリを開いても壊れない
- 新規生成したレポートに previous_action_review と open_loops が入る
- sw.js 先頭の CACHE_VERSION をインクリメントする（上げないと古いSWが居座り
  デプロイが反映されない。README「オフライン対応」節に運用ルールの記載あり）

python3 -m http.server 8000 で起動して動作確認してから、
ベースブランチ claude/personal-cns-diary-platform-exbv7x から新しいブランチを切って
コミット＆プッシュし、PRを作成すること。
```

## ② 自己申告の気分 vs AI観測の気分を重ねる（API不要・最短で最大の洞察）

```
リポジトリ dr-sakamoto/memo を改修したい。

【アプリの前提】
自分ひとり用のCNS（日記/思考ログ）。依存ゼロの静的Webアプリ。
index.html + css/style.css + js/*.js（ES Modules、ビルドなし）、データは全部localStorage。
グラフは全部インラインSVGを手書きしている（チャートライブラリは入れていない）。

【解きたい問題】
自己分析に使える最大の未使用資産が眠っている。
- ユーザーが投稿時に自己申告した気分（post.mood, -2〜+2）→ js/app.js の renderMoodChart()
- AIがレポートで観測した気分（report.data.mood_score）→ js/app.js の renderMetaAnalysis()
この2つが別々のチャートに描かれていて、突き合わせがない。
「自己認識と他者観測のズレ」こそ自己分析の核心で、データは両方すでに手元にある。
新たなAPI呼び出しは一切不要。

【やること】
1. js/report.js に selfReportedMoodByPeriod() を追加。
   各レポートの from〜to 区間に入る posts のうち mood != null のものを平均し、
   { periodKey, periodType, label, from, selfMood, aiMood } の配列を返す。
   自己申告が0件の期間は selfMood: null とする。

2. js/app.js のレポートビューに「自己認識のズレ」カードを新設し、
   同一のx軸（レポート単位・時系列）に2系列を重ねたSVG折れ線を描く。
   - 自己申告: 実線
   - AI観測: 破線
   - 各点に <title> でツールチップ（期間ラベルと両方の値）

3. 乖離の強調。|selfMood - aiMood| >= 0.8 の期間は点を大きく描き、
   カード下部に「この期間、あなたの自己申告と他者の観測は大きくズレている」
   という趣旨の一文＋該当期間ラベルを列挙する。

4. 既存の #moodChart（直近30日のローカル統計）はそのまま残す。役割が違う。

【制約】
- npm依存・チャートライブラリを導入しない（既存と同じくSVG手書き）
- selfMood が null の期間は線を途切れさせる（0として描かない）
- レポートが2件未満のときはカードごと hidden にする（既存の #metaCard と同じ挙動）
- 週次レポートと月次レポートを同じ線に混ぜないこと。
  ※既存の reportTimeSeries()（js/report.js）は両者を from でソートして1本の線に
    混ぜており解釈不能になっている。このタスクの新チャートでは同じ轍を踏まず、
    periodType ごとに系列を分けること

【完了条件】
- レポートが週次・月次混在で存在しても、それぞれ独立した系列として正しく描かれる
- sw.js 先頭の CACHE_VERSION をインクリメントする（上げないと古いSWが居座り
  デプロイが反映されない）

python3 -m http.server 8000 で起動し、Playwrightでスクリーンショットを撮って
グラフが破綻していないことを確認してから、
ベースブランチ claude/personal-cns-diary-platform-exbv7x から新しいブランチを切って
コミット＆プッシュし、PRを作成すること。
```

## ③ 年次ロールアップ — レポートを入力にした熟成レイヤー

```
リポジトリ dr-sakamoto/memo を改修したい。

【アプリの前提】
自分ひとり用のCNS（日記/思考ログ）。依存ゼロの静的Webアプリ。
index.html + css/style.css + js/*.js（ES Modules、ビルドなし）、データは全部localStorage。
js/workflow.js に「正規化→抽出(map)→統合(reduce)→照合」の多段パイプラインがあり、
無造作な雑記を固定スキーマのJSONレポートに落とし込んでいる。
AI APIはユーザー自身のキーでブラウザから直接叩く（Claude / Gemini 切替可）。

【解きたい問題】
生成できる期間が週次と月次しかない（js/report.js の listGeneratablePeriods）。
「自己コンテキストの歴史熟成」の本体は、posts ではなく reports を入力にした
上位のreduce（四半期・年）なのに、その階層が存在しない。

1. js/report.js の listGeneratablePeriods() に四半期・年次を追加する。

   - 繰り返し指摘され続けた盲点は何か（＝熟成ではなく停滞のサイン）

【制約】
- npm依存・ビルドツールを導入しない
- 既存のlocalStorageデータを破壊しない
- ロールアップレポートも既存の REPORT_SCHEMA に従わせる（新スキーマを作らない）。
  レポート横断のメタ分析が壊れないことが最優先
- reread_post_ids はロールアップでは実在するpost idに絞り込めるとは限らないので、

【完了条件】
- 週次・月次レポートが十分に貯まっていない状態でも、UIが壊れずに

- sw.js 先頭の CACHE_VERSION をインクリメントする
```

## ④ 盲点への応答 — 第三者視点を一方通行から対話にする

```
リポジトリ dr-sakamoto/memo を改修したい。

【アプリの前提】
自分ひとり用のCNS（日記/思考ログ）。依存ゼロの静的Webアプリ。

【解きたい問題】
盲点の指摘が完全に一方通行になっている。ユーザーが「当たっている／外している」を

   レポートに feedback.at のようなタイムスタンプを持たせ、
   「feedbackが新しい方を残す」ピック関数に差し替えること。

【制約】
- npm依存・ビルドツールを導入しない
- 既存のlocalStorageデータを破壊しない（feedback が無いレポートは従来通り表示）
- ユーザーの応答は任意。無記入でもレポートは成立する
- 「AIの断定を鵜呑みにしない装置」として反論の導線を弱くしないこと。

【完了条件】

- sw.js 先頭の CACHE_VERSION をインクリメントする
```

## ⑥ メタ分析の修正 — 週次と月次の混線（実質バグ）＋テーマのライフサイクル

```
リポジトリ dr-sakamoto/memo のバグ修正と機能追加をしたい。

【アプリの前提】
自分ひとり用のCNS（日記/思考ログ）。依存ゼロの静的Webアプリ。
index.html + css/style.css + js/*.js（ES Modules、ビルドなし）、データは全部localStorage。
週次/月次のAIレポートが貯まると、レポートタブに「メタ分析」カードが出る。
グラフはインラインSVGの手書き（チャートライブラリ不使用）。

【バグ】
js/report.js の reportTimeSeries() は全レポートを from でソートして返し、
js/app.js の renderMetaAnalysis() がそれを単一の <path> で結んでいる。
そのため週次レポートと月次レポートが1本の折れ線に混ざり、
月次の点が週の点の間に刺さって、推移として解釈不能になっている。

【やること】
1. reportTimeSeries() を periodType ごとにグループ化して返す形に変える
   （呼び出し側の app.js も追従させる）。

2. renderMetaAnalysis() のグラフを periodType 別の系列にする。
   週次と月次を別々の線として描く（色分け＋凡例）か、切替タブにする。
   どちらでもよいが、異なる粒度を1本の線で結ばないこと。

3. テーマのライフサイクル表示を追加する。
   現在の recurringThemes() は出現回数を数えるだけなので、
   各テーマについて 初出の期間 / 最終出現の期間 / 出現回数 / 現在も継続中か
   を算出し、「いま生きているテーマ」と「消えたテーマ」を分けて表示する。
   ※ここが「歴史の熟成」を可視化する肝なので、単なる回数の羅列にしないこと。

4. 同じ blind_spot が繰り返し出ているかの検出を追加する。
   完全一致は期待できないので、日本語のまま比較できる素朴な手法
   （記号・空白除去のうえでのbi-gram Jaccard係数など、外部ライブラリなし）で
   類似度を取り、閾値以上のものを「繰り返し指摘されている盲点」として提示する。
   これは熟成ではなく停滞のサインなので、目立つ扱いにする。

【制約】

- 既存のlocalStorageデータを破壊しない

- sw.js 先頭の CACHE_VERSION をインクリメントする
```
