# 🍇 MEMO — 過去の自分が流れてくるSNS

🔗 **[アプリを開く](https://dr-sakamoto.github.io/memo/)**（GitHub Pages）

Xとメモ帳のあいのこ。書く操作はXと同じで、タイムラインに流れてくるのは**過去の自分の投稿だけ**。
SNSを開きたくなったときの置き換え先として、**AIを使わずアルゴリズムだけ**で組んでいる。

## 画面

- **ホーム** — 上から「いま書いたもの」「今日の節目」「流れてきた過去のあなた」
- **記録** — 全投稿の時系列。本文検索とタグ絞り込み
- **設定** — 「もう流さない」の解除、クラウド同期、バックアップ

## アルゴリズム（`js/flow.js`）

部品は3つだけ。重要度（引用・再掲の回数など）は使わない。よく考えていることばかり流れると、思考がそこへ吸い寄せられ、過去の自分との思いがけない再会が起きにくくなるため。

| 部品 | 中身 |
|---|---|
| **節目** | 「1年前の今日」「3ヶ月前の今日」「1週間前の今日」のような暦の一致。ホームの上に最大3件 |
| **流れ** | 1日以上前の投稿を、ほぼ一様ランダムで重み付き抽出。重みは忘却曲線 `1 − exp(−経過日数 / 14)`。経過日数は「最後に流れてから」（一度も流れていなければ投稿から）。最近流れたものほど出にくく、長く流れていないものほど戻ってくる。1回の流れでは同じ連から1件だけ |
| **こだま** | 刻んだ直後に、似たことを書いていた過去の投稿を最大3件返す。文字bigramのJaccard係数＋同じタグで加点。AI返信の代わりの「すぐ返ってくる反応」 |

止めどき:
- 流れは開いたときに15件だけ組み、勝手に入れ替えない（無限に更新されるスロットにしない）。「もう少し流す」で10件ずつ足す
- 1日に45件流れたら「今日はここまで」の合図を出す（それでも続けることはできる）
- 30分以上離れて戻ってきたら、新しい流れを組み直す

「いつ流したか」「もう流さない」は端末ローカル（`cns.surface.v1`）に持ち、投稿データには書き込まない。

## 投稿のしくみ

- **刻む** — 本文だけ。`#タグ` は自動で拾う。Ctrl/Cmd+Enterでも投稿できる
- **連（スレッド）** — 直前の投稿から5分以内なら自動で同じ一息として束ねる。記録タブの ✂️ で切り離せる
- **接ぎ木（引用）** / **再掲** — 流れてきた過去の自分に、いまの自分を重ねる
- **もう流さない** — 流れてほしくない投稿を外す（削除はしない）

## 使い方

ES Modulesを使っているため、ローカルHTTPサーバーで開きます：

```sh
cd memo
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

### オフライン対応（Service Worker）

`sw.js` がアプリシェル（`index.html` / `css/style.css` / `js/*.js` / `manifest.webmanifest` / `icons/`）をインストール時にプリキャッシュし、`fetch`はcache-firstで返す。データはlocalStorageのみなのでキャッシュ対象は静的資産だけである。**運用ルール**: `index.html`・CSS・JS・アイコンなど、シェルの中身をデプロイで変更したら、必ず`sw.js`先頭の`CACHE_VERSION`をインクリメントすること。バージョン文字列を上げないとブラウザは`sw.js`自体の変更（バイト差分）を検知できず、古いService Workerが居座って新しいデプロイがユーザーに反映されない「更新の罠」が発生する。バージョンを上げれば、次回アクセス時に新しいキャッシュがインストールされ、`activate`時に古いバージョンのキャッシュが破棄される。

## クラウド同期 — スマホ⇔パソコン（`js/sync.js`）

**「完全ローカル・依存ゼロ・中間サーバーなし」を崩さないまま、複数端末で同じ雑記を育てる。** ライブラリを足さず、ユーザー自身が用意したSupabaseの Auth(GoTrue) と REST(PostgREST) を`fetch`で直接叩く。接続先（Project URL / 公開キー）は設定タブで上書きできる。

- **セットアップ** — 既定の接続先（Supabaseプロジェクト）が `js/sync.js` に埋め込み済みで、**利用者は接続設定なしで、両端末で同じアカウントにログインするだけ**で同期が始まる。ログインしなければ従来どおり完全ローカルで動作する。自分のSupabaseに切り替えたい場合は `docs/supabase-setup.sql` の手順でプロジェクトを作り、設定タブの「接続先の設定」でURLと公開キー（anon / publishable key）を上書きする。
- **同期する対象** — 投稿（旧版のレポートがあればそれも）のみ。設定と「流した記録」は同期しない（端末ごとに保持）。
- **保存形式** — `memo_state` テーブルにユーザーごと1行、`data`(jsonb) に投稿（旧版のレポートがあればそれも）をまるごと保存。Row Level Security により、ログイン本人の1行しか読み書きできない（公開キーを埋め込んでも他人のデータは覗けない）。
- **マージ方針** — 端末Aと端末Bのデータを **id で突き合わせて和集合**を取る（同一idは引用/再掲が多い方を残す）。これにより**どちらの端末で書いた分も失わない**。削除は「墓標（削除済みid）」として同期し、他端末に残っていても復活しない。
- **同期のタイミング** — 起動時 / データ変更時（1.5秒デバウンスの自動プッシュ）/ 画面復帰時（`visibilitychange`）。設定で自動同期をOFFにすると「今すぐ同期」ボタンのみになる。
- **オフライン整合** — Service Worker は `*.supabase.co` への通信をキャッシュ対象から明示的に除外し、常にネットワークへ素通しする。

## ファイル構成

```
index.html      — SPA本体
css/style.css   — スタイル
js/store.js     — データ層（localStorage、連の自動束ね、変更通知フック）
js/flow.js      — 流れのアルゴリズム（節目・忘却つきランダム・こだま・1日の流量）
js/sync.js      — クラウド同期層（Supabase Auth/RESTを直接fetch・id和集合マージ）
js/app.js       — UIコントローラ
sw.js           — Service Worker（アプリシェルのオフラインキャッシュ）
docs/supabase-setup.sql — クラウド同期用テーブル/RLSの作成SQLとセットアップ手順
```

## 旧版からの移行

AIレポート・AI返信・ブドウの木・電光掲示板・時間軸ビュー・気分入力は外した。既存データはそのまま読める。

- 投稿（`cns.posts.v1`）はそのまま。過去に記録した気分は表示だけ残る
- 旧版のレポート（`cns.reports.v1`）は画面には出ないが、消さずに同期・エクスポートで持ち運ぶ
- `docs/next-tasks*.md` は旧版（AIレポート路線）の作業メモ
